StockPro - System Requirements

Software Requirements Specification (bazat pe IEEE SRS Template)
Pădurariu Alexandru, Ștefanache Cosmin

1. Rezumat (Abstract)

Proiectul StockPro reprezintă o aplicație Web dedicată gestionării eficiente a stocurilor de articole esențiale, consumabilelor și pieselor de schimb (ex: unelte, electronice, articole de uz casnic etc.). Sistemul este proiectat pentru a fi implementat în cadrul unei gospodării, organizații sau întreprinderi. Platforma automatizează procesul de monitorizare a stocurilor, generând notificări în interfață și prin e-mail la epuizarea iminentă a resurselor sau la termenele de inspecție. Prezenta documentație Scholarly HTML definește setul de cerințe funcționale și non-funcționale conform standardului IEEE.

2. Introducere

2.1 Scopul Documentului

Scopul acestui document este de a descrie arhitectura și cerințele sistemului software StockPro. Acesta include o descriere detaliată a interacțiunii utilizatorului cu aplicația web și o specificare tehnică a serviciilor backend.

2.2 Public Țintă

Aplicația se adresează utilizatorilor sau administratorilor care doresc eficientizarea gestiunii depozitului propriu, reducerea pierderilor cauzate de expirarea materialelor și monitorizarea consumului prin rapoarte exportabile.

3. Descriere Generală

3.1 Perspectiva Produsului și Arhitectura

Produsul este dezvoltat pe arhitectura Client - Server, fiind bazat exclusiv pe Servicii Web (RESTful API). Backend-ul este procesat folosind limbajul PHP, iar stocarea datelor se face într-o bază de date relațională (MySQL). Frontend-ul este un Single Page Application (SPA) simulat sau hibrid, construit respectând standardele web cu HTML5, CSS3 și JavaScript (Vanilla). Nu s-a utilizat niciun framework. Comunicația între client și server se face asincron, prin AJAX (Fetch API) utilizând formatul JSON.

3.2 Interacțiunea cu Utilizatorul

Utilizatorul interacționează cu sistemul prin intermediul unui meniu lateral (Sidebar) care facilitează accesul la modulele: Dashboard, Categorii, Articole, Notificări, Import/Export și Administrare. Toate acțiunile (CRUD) se realizează dinamic, răspunsul fiind afișat prin notificări tip pop-up (Toast) și ferestre modale, pentru a menține o navigare cursivă fără reîncărcarea paginii.

4. Cerințe Funcționale

4.1 Managementul Categoriilor

  • Sistemul trebuie să permită vizualizarea unei liste dinamice de categorii, cu contorizarea automată a numărului de articole per categorie.
  • Utilizatorul trebuie să poată crea, redenumi și șterge categorii.

4.2 Managementul Articolelor (Stocurilor)

  • Aplicația trebuie să permită înregistrarea de noi articole specificând: Nume, Categorie, Cantitate, Prag minim de alertă, Data ultimei verificări.
  • Informațiile despre articole pot fi modificate, iar stocurile pot fi actualizate numeric în orice moment.
  • Modulul trebuie să conțină un sistem de filtrare și căutare live (după text, categorie și starea stocului: OK / Stoc redus / Epuizat).

4.3 Alerte și Notificări Inteligente

  • Aplicația trebuie să genereze automat o notificare internă pentru fiecare produs a cărui cantitate scade sub sau este egală cu Pragul minim de alertă.
  • Se vor genera alerte pentru articolele (ex. echipamente tehnice, mașini) a căror dată de verificare este mai veche de o perioadă stabilită (ex. 30 zile).
  • Sistemul trebuie să poată compila aceste alerte și să trimită rapoarte prin e-mail, funcționalitate declanșabilă din aplicație sau cron-job.

4.4 Import și Export de Date

  • Export: Sistemul trebuie să genereze și să descarce inventarul în 3 formate deschise: CSV, JSON și XML.
  • Import: Utilizatorul trebuie să poată popula rapid inventarul prin încărcarea fișierelor cu structură standardizată (CSV, JSON, XML).
  • Statistici: Rapoartele generate se pot consulta sub formă HTML și pot fi exportate direct în format PDF prin mecanismele browserului.

5. Cerințe Non-Funcționale

5.1 Securitate

  • Sistemul backend va utiliza interogări pre-compilate (Prepared Statements prin extensia PDO) pentru a neutraliza orice tentativă de SQL Injection.
  • Datele afișate în interfața clientului sunt sanitizate pentru a preveni atacurile Cross-Site Scripting (XSS) folosind funcții de escape (ex. transformarea caracterelor speciale în entități HTML).

5.2 Design Web Responsiv (RWD)

  • Aplicația trebuie să garanteze o funcționalitate vizuală corectă pe rezoluții variate (desktop, tabletă, dispozitive mobile). Interfața se readaptează dinamic pe lățimi mici de ecran folosind Media Queries din CSS.

5.3 Respectarea Principiilor Ingineriei Software

  • Codul trebuie să fie modularizat (separarea responsabilităților: Router, Controlere API, Scripturi Frontend per secțiune) și comentat descriptiv.
  • Dezvoltarea aplicației s-a realizat iterativ folosind sistemul de management al versiunilor (Git).
